Which desktop shell should Cader use? Your follow-up: is Tauri + Rust mature enough for llama.cpp and the other runtimes? Short answer: yes, and it fits D-3 best.

Rust runtimes for each model:
- **Whisper (S-3):** whisper-rs (whisper.cpp bindings, Metal). Handy is itself a Tauri + Rust app running Whisper this way, so its engine code (MIT) can be reused directly, which is what D-3 asked for.
- **Qwen2.5-1.5B (S-4):** llama-cpp-2 crate (llama.cpp bindings, Metal feature), actively maintained and used in shipping apps.
- **CoEdIT-large ONNX (S-4):** ort crate (ONNX Runtime bindings), mature, CoreML/CPU on macOS.
- Tauri 2 has been stable since late 2024; Spill and Handy both run on it.

Trade-offs: Rust compile times and a steeper language for the backend; in return a small app (system webview), models in-process with no Node native-module rebuilds, and the Handy engine reused as is. The UI stays TypeScript, built with Bun.

- A. Electron, with Bun as package manager and bundler (Node main process; onnxruntime-node, node-llama-cpp, whisper as a separate sidecar binary)
- B. Electrobun (Bun main process, system webview; youngest option, native ML modules need extra work)
- C. Tauri 2: Rust backend running whisper-rs, llama-cpp-2 and ort in-process, TypeScript UI built with Bun (recommended)
