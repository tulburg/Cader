## Purpose

A standalone desktop app that holds every Cader document locally, with no account and no network calls at runtime (models are downloaded once).

## Requirements

1. The app is a Tauri 2 app (D-6): a Rust backend in `src-tauri/` and a TypeScript UI in `ui/`, whose dependencies, scripts and bundling run on Bun (`bun install`, `bun run dev`, `bun run build`).
2. It builds a macOS .app; Windows and Linux builds are not required for v1.
3. Documents are stored as files in a Cader library folder in the user's home directory, one folder per document.
4. A library view lists documents with title, last edited time and status (draft or saved, D-7), and creates, opens, renames and deletes them. There is one kind of document: a single New button creates one titled "Untitled", and no kind is shown.
5. The UI reaches files, dictation and the models only through typed Tauri commands; the webview has no direct file system access.
6. Nothing leaves the machine: no telemetry, no remote API calls after model download.

## Out of scope

- Cloud sync, accounts, collaboration.
- Mobile apps.

## Acceptance checks

- `bun run dev` opens the app window on macOS.
- Creating a document writes its folder to the library; reopening the app lists it.
- The library shows one New button and no Speech or Blog tag; New opens an "Untitled" document.
- The webview cannot read files outside the commands Cader exposes.
- No outbound network request during a dictation and review session (checked with a proxy).
